# Exploratory User Interviews Record

**Date of Interviews:** October 18-20, 2026
**Target Audience:** Adult undergraduate students
**Methodology:** Semi-structured interviews focusing on recent experiences with browser security warnings.

## Summary of Findings

| Discussion Topic | Anonymised Situation & Decision Difficulty | Requirement Informed |
| :--- | :--- | :--- |
| **A recent uncertain website decision** | Participants reported anxiety when facing generic "Red Screen" blocks on university or payment portals. They often bypass warnings if they are in a hurry. | F01, F06 (Concise result) |
| **What makes a warning understandable** | Users ignore technical jargon (e.g., "invalid certificate"). They explicitly requested to see *why* the page is blocked (e.g., "The form sends data to a different website"). | F05, F07 (Evidence and explanation) |
| **Legitimate login and false alarms** | Two participants noted that Chrome sometimes flags legitimate OAuth popups (e.g., logging in via Google/Kaspi). | F04, F08 (Trusted origins & exceptions) |
| **Local processing and hardware** | Participants expressed discomfort with extensions that read their browsing history or upload passwords to the cloud. | N01, N04 (Zero-data leakage, local execution) |

*Note: These records inform the requirements of the Hybrid Edge AI architecture. No specific user quotes or percentages are claimed as statistical proof.*
